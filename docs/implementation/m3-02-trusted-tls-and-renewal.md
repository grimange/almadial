## S08 ownership and validation

`internal/provision/tls*.go`, `tls_native.py` and `cmd/almadial-tls` implement a
bounded stage using the accepted plan, runner, lock and journal. Typed
`TLSRequest` supplies mode, hostname, certificate, private-key and trust-file
paths. `TLSCertificate` and plans contain only public identities and validity.
Go verifies PEM parsing, key pairing, current validity, SAN identity, server-auth
usage, intermediates and the explicit trust anchors before native activation.
Malformed public material and private-key blocks in public inputs fail closed.
Protected input files are bounded regular files opened without following a final
symlink; private keys require root ownership, owner read/write, no world access
and an approved root/asterisk group. Keys travel to the bounded native adapter
only through stdin, never argv, environment, logs or evidence.

The one action, `tls.00.activate`, performs a certificate transaction:

1. Recheck the observed filesystem identity and closed configuration ownership.
2. Stage the validated generation, checking the actual staged key pair.
3. Atomically replace the `current` symlink and publish exact owned configuration.
4. Validate Apache, gracefully reload Apache and reload Asterisk's built-in HTTP
   module, then verify trusted endpoint and application postconditions.
5. Retain the previous successful generation through `previous` after renewal.

Storage is `/etc/pki/tls/almadial-s08/<public-certificate-identity>/` with
`fullchain.pem`, `key.pem` and `trust.pem`; directories are root:asterisk 0750,
files root:asterisk 0640 with `cert_t`. `current`/`previous` are root-owned local
relative symlinks. The private CA signing key is only a protected laboratory
fixture under `/root`; it is not an installer input or deployed endpoint key.

Exact root:root 0644 `httpd_config_t` files:

- `/etc/httpd/conf.modules.d/99-almadial-s08.conf`, including the S08 vhost.
- `/etc/httpd/almadial-s08.conf`, generated by `TLSVhost()` from the accepted S07
  routes, authorization handling, PHP socket and sensitive-file denials.

The vhost adds `Listen 127.0.0.1:443 https`, a matching virtual host,
`SSLEngine on`, TLS 1.2/1.3, and certificate/key references through `current`.
Existing S07 HTTP configuration and foreign Apache/PHP files are preserved.
The only Asterisk configuration change is root:asterisk 0640 `etc_t`
`/etc/asterisk/http.conf`:

```ini
#include almadial-s04-http.conf
[general](+)
tlsenable=yes
tlsbindaddr=127.0.0.1:8089
tlscertfile=/etc/pki/tls/almadial-s08/current/fullchain.pem
```

The original S04 fragment remains unchanged. Activation commands are:

```sh

```

No Asterisk process restart, SIP transport, public listener, firewall change,
AMI grant change or VICIdial source/schema modification is required.

## Execution, recovery and reproducibility

The CLI provides `inspect --accepted-web FILE --request FILE`, pure
`plan --input FILE`, and authorized `lab-run`/`lab-resume`. All take the same
accepted pinned source flags as S07:

```text
--manifest FILE --source FILE --perl-source FILE --asterisk-source FILE
--signature FILE --keyring FILE --scratch DIR --pjproject FILE
```

Lab execution additionally requires `--authorization FILE --state-dir DIR`.
`--help` documents the supported command surface. An example nonsecret request:

```json
{"Mode":"provided","Hostname":"localhost","CertificateFile":"/root/tls-input/fullchain.pem","PrivateKeyFile":"/root/tls-input/key.pem","TrustFile":"/root/tls-input/trust.pem"}
```

Authorization binds the exact host, stage, parent, manifest, policy, snapshot
reference and operator evidence; scope is `ALM-24/disposable-lab`, with explicit
CANDIDATE acknowledgment and dialing inactive. `journal.Acquire`, durable intent,
bounded commands, fresh postconditions and persisted outcomes use the existing
execution contract. Material/source/plan drift and lock contention reject
execution. Complete effects reconcile from inspection; unknown/partial effects
block replay and require fresh assessment. Transaction failure reverses only its
known pointer/configuration preimage and reloads the old configuration. If that
recovery reload fails too, execution fails and requires operator inspection; it
does not claim working endpoints. Staged generations remain available.

Actual qualification used `/tmp/alm24-qualification/tls` with accepted S07 input
and the already pinned source artifacts under `/tmp/alm19-qualification` and
`/tmp/alm20-qualification`; protected command artifacts record exact argv.
The product does not create a new supervisor, CA service or installation engine.
The manifest remains CANDIDATE, and the M2 governance clarification is unchanged.
